# Implementation contract

The application uses the existing Go Fiber/GORM backend and Vue/TypeScript frontend. All private routes are under `/api/v1`, use the existing cookie session and `X-TAS-CSRF: 1` for mutations. JSON property names are snake_case. Entity IDs are numeric.

## Workspace API

- `GET /tournaments`, `POST /tournaments`, `PUT /tournaments/:id`, `DELETE /tournaments/:id`
- `GET /tournaments/:id/workspace` returns `{tournament, leagues, stages, fields, slots, teams, referees, matches, standings, published_standings}`. Lists are always arrays. Standings entries include `league_id, stage_id, team_id, played, wins, draws, losses, scored, conceded, difference, points, rank`.
- `POST /tournaments/:id/{leagues,stages,fields,slots,teams,referees,matches}` creates an entity; `PUT /{collection}/:id` and `DELETE /{collection}/:id` update/delete. Creates and updates return the entity directly. Errors return `{error: string}`.
- `PUT /matches/:id` accepts pre-start metadata only (teams, stage, duration, round, notes) for administrators/editors; existing assignments are revalidated. Result and live-state fields are server owned. Score changes use referee control or result review.
- `POST /stages/:id/prepare` (administrators only) idempotently reconciles empty games and returns `{matches:Match[],stage:Stage}`. Automatic stages reconcile on stage saves and roster changes; existing empty stages are also prepared at startup. Workspace reads never create games.
- `POST /stages/:id/preview` with optional `{round:number}` returns `{matches:Match[],preview_token:string,round:number}` without writes or match-ID consumption. For prepared games the preview targets existing match IDs/numbers; newly awarded byes have provisional numbers.
- `POST /stages/:id/generate` with `{round?:number,preview_token?:string}` populates the existing round-robin, Swiss, or knockout games atomically, preserving IDs, numbers, timeslots, fields, referees, and publication; conflicts roll back every assignment. Returns `{matches:Match[],round:number}`. New clients supply the preview token; stale plans return 409 with no writes. Individual-run stages and prepared Swiss/knockout stages contain one round and reject another population until cleared; create a linked stage for the next round. Source-stage games must all have teams and approved results before seeding. Legacy stages without preparation metadata retain their existing generation support. Tokenless calls remain available to existing clients.
- `POST /stages/:id/matches` with `{matches:[{team1_id,team2_id,duration_minutes,round,notes?}]}` creates a manually reviewed batch of 1–256 matches atomically and returns `{matches:Match[]}` with status 201. League/tournament ownership is derived from the stage. Validation failure leaves the entire batch uncreated.
- `POST /stages/:id/clear` (administrators only) with `{}` clears the stage draw; optional `{round:positiveInteger}` clears a round. Round-robin stages require clearing the whole draw. Returns `{cleared:number,round:number,stage:Stage}`, where `round:0` denotes the whole draw. For automatic stages, clearing resets team assignments to empty placeholders and keeps bookings/publication; generated byes are removed. Manual stages remove the match rows and their assignments/publication. The stage, configuration, teams, fields, timeslots, and referee roster are retained. The stage's `round` becomes the highest remaining populated round, or 0. Started/submitted/approved games block the operation, except automatically awarded byes. Later populated rounds and explicit or inferred seeded stages with assigned teams must be cleared first; empty reserved games do not block source changes. All validation and removal occur atomically under the tournament lock; conflicts return 409 without partial changes. Empty clears are idempotent. Omit `round` to clear all; explicit 0, null, negative, fractional, or nonnumeric values return 400.
- `POST /stages/:id/standings/publish` (admin/editor) saves the current approved, public standings as a snapshot and returns `{league_id,stage_id,published_at,rows}`. A real approved/public non-bye result is required. Individual-run completion counts as a real result, without soccer points.
- `DELETE /stages/:id/standings/publication` (admin/editor) withdraws a saved snapshot (204). Disable auto mode first; withdrawal while auto mode is enabled returns 409.
- `PUT /leagues/:id/standings-settings` (admin/editor) with `{auto_publish:boolean}` returns `{league,publication:latestSnapshot|null}`. Turning auto mode off atomically freezes the effective auto tables; enabling it uses current eligible results. Public GETs never persist publications.
- `POST /fields/:id/copy-slots` with `{source_field_id: number}` copies availability.
- `POST /matches/:id/schedule` with `{slot_id: number|null, referee_ids: number[]}` assigns a slot/referees or unschedules. The server checks field league, duration, team/referee overlaps and referee availability.
- `POST /matches/:id/review` with `{approve: boolean, notes?: string, goals1?: number, goals2?: number}` approves/publishes or returns the submitted result for correction. Individual runs can be approved directly without live referee control; approval marks them complete and awards no head-to-head or bye points.
- `POST /matches/:id/publish` with `{published: boolean}` controls schedule visibility. Only approved results are public.

## Entities

- Tournament: `id,name,abbrev,start_date,end_date,timezone` (dates YYYY-MM-DD; IANA timezone).
- League: `id,tournament_id,parent_id` (nullable for main leagues), `name,abbrev,mode` (`full` or `scheduling`), `referee_mode,inspections_enabled` (defaults to true, including existing leagues), `robot_count,max_weight_g` (0 means unlimited), `ball_zone_cm,voltage,size_cm,motor_limit,half_seconds,halftime_seconds,standings_auto_publish` (defaults to true independently for each league).
  The setup UI creates main leagues before sub-leagues. Main-league forms edit identity and management/referee controls; sub-league forms require an existing main league and edit inspection/clock settings. Children inherit `mode` and `referee_mode`; updates to the main league preserve child inspection and timer settings. Existing records remain compatible with the shared entity representation.
  `inspections_enabled` belongs to each sub-league and is not inherited. When false, physical inspection limits are retained and referee setup skips the checklist. Clock inputs are disabled when inherited `referee_mode` is false; stored durations are retained. With referee mode off, the API rejects live match-control commands.
- Stage: `id,tournament_id,league_id,name,type` (`round_robin,swiss,knockout,individual,manual`), `sort_order,source_stage_id` (nullable), `round,team_limit` (0 means all teams), `expected_teams` (0 uses the registered sub-league roster, capped by `team_limit`). Positive counts are 2–256 for paired stages or 1–256 for individual runs. Automatic round-robin stages reserve the full round robin; Swiss and knockout reserve one round per stage. `round` tracks populated rounds only. Every nonmanual stage reserves games in either league mode. Individual-run stages reserve one game per team in round 1. Manual stages do not reserve games automatically.
- Field: `id,tournament_id,league_id,name`.
- Slot: `id,tournament_id,field_id,starts_at,ends_at` (RFC3339 instants).
- Team: `id,tournament_id,league_id,name,affiliation,startnumber,external_key`.
- Referee: `id,tournament_id,name,user_id,available_from,available_until` (nullable RFC3339, optional availability bounds).
- Match: `is_placeholder,id,tournament_id,league_id,stage_id,number,round,team1_id,team2_id` (nullable for a bye, individual run, or manual scheduling-only solo run), `is_bye,field_id,slot_id,scheduled_at` (nullable), `duration_minutes,referee_ids` (array), `goals1,goals2,status` (`draft,scheduled,in_progress,submitted,approved`), `published,notes,live_state,updated_at`.

## Referee API

- `GET /matches/:id` returns a Match.
- `POST /matches/:id/control` accepts `{action, ...}` and returns the updated Match.
- Actions: `checks` with `{checks: RobotCheck[]}`; `setup` with `{blue_team_id,kickoff_team_id}`; `start`, `pause`, `advance` (optional `{force:true}` to skip an unfinished period); `goal` with `{team_id,delta: 1|-1}`; `timeout` with `{team_id,robot:number}` (1-based) to start/reset a minute; `timeout_clear` with the same robot/team fields to return to play; `finish_early` with `{reason:string}` (1–1000 characters); `submit` with `{signatures:Signature[],notes}`. Early finishes preserve scores and require the normal signatures and editor review.
- `live_state` is an object: `{checks: RobotCheck[],phase: 'pregame'|'ready'|'first_half'|'halftime'|'second_half'|'finished',remaining_seconds: number,running: boolean,started_at: string|null,blue_team_id: number|null,kickoff_team_id: number|null,timeouts: {team_id,robot,ends_at}[],signatures: Signature[],signed_goals1?:number,signed_goals2?:number}`. `remaining_seconds` is the timer at `started_at`; clients derive elapsed time while running, using the `X-Server-Time` response header to correct device clock skew. `advance` without `force:true` only succeeds after expiry: first_half -> running halftime, halftime -> paused second_half (switches sides/kickoff), second_half -> finished. `start` starts a ready/paused phase. Pregame setup requires valid checks for all robots when `inspections_enabled` is true. Otherwise checks are skipped, while sides and kickoff setup remain required. Changing the inspection flag resets only that league’s unstarted matches to pregame, retaining schedules and referee assignments. Kickoff requires at least one assigned referee. `submit` requires finished phase and signatures for both teams and all assigned referees, and snapshots the signed score. Returning a report for correction clears signatures for renewed acceptance.
- RobotCheck: `{team_id,robot,weight_g,ball_zone,voltage,size,motors}`. Signature: `{kind:'team'|'referee',id:number,name:string,signature:string}` (signature is a drawn PNG data URI).
- Live state also contains `events:MatchEvent[]`, `ended_early:boolean`, and private `end_reason?:string`. `MatchEvent` is `{id,at,type,phase,remaining_seconds,team_id?,robot?,side?,next_phase?,forced?}`; IDs increase within each match. Event sides are snapshots of blue/yellow at the time of the action. Events cover starts, pauses, goals/removals, timeout starts/resets/returns, period advances, and normal/early endings. Existing matches default to an empty log.

## Public API

- `GET /api/public/tournaments` lists tournaments.
- `GET /api/public/:abbrev` returns the same workspace shape, restricted to published schedules, approved scores and public live timer/score; excludes checks, signatures, referee user IDs and private notes. Public `standings` contains only the latest published stage per exact league; `published_standings:[{league_id,stage_id,published_at,rows}]` provides those snapshots and publication times. Private `standings` remains live for all stages; private `published_standings` contains every effective stage publication. Latest means highest stage `sort_order,id`, not the latest match edit. Auto mode computes eligible tables without GET writes; manual snapshots persist unchanged until republished or invalidated by a source-result withdrawal.
- The public live-state allowlist includes safe typed events and `ended_early`, excluding private early-ending reasons. Goal and goal-removal events are hidden whenever the pending final score is hidden; non-goal events remain visible.
- Catigoal-compatible `GET /rest/v1/:abbrev/leagues`, `/matches`, and `/standings` retain their default object envelopes and legacy `league` / `league_stage` parameters. `format=openapi` selects the original array wrappers. Only published games appear; goals and points remain zero until approval.
- `/leagues` adds `main_leagues:[{id,abbrev,name,league_stages,sub_leagues}]` for hierarchical discovery, including roots and children with no stages. The legacy flat `leagues` array still excludes leagues without stages. Flat league entries include `id,parent_id,main_league_abbrev,main_league_name,sub_league_abbrev,sub_league_name`; root entries have null sub-league fields.
- All three endpoints accept `main_league=ROOT_ABBREV` and `sub_league=CHILD_ABBREV`. Main selection scopes its root plus children; sub selection selects one child. Legacy `league` remains exact and is an alias for sub selection only when its value identifies that child. Supplying both exact selectors requires identical values; an explicit parent must match the selected league. Invalid selections return 404 `{error:string}`. Standings requires an exact league/sub-league; main-only selection does not aggregate tables.
- `league_stage` applies to matches and standings, requires an exact league/sub-league, and indexes its complete stage catalog from 0 in `sort_order,id` order. The league catalog is never narrowed by stage index. Omitting the stage on standings returns the latest published snapshot with the legacy Seeding label and empty stage-number string. `published_stage_id/name/number` identifies the actual source; `standings_publishing_state` is PUBLISHED or UNPUBLISHED. Unpublished requests return an empty table, empty publication time, and null published-stage fields. `league_stage_number` is a JSON string in legacy envelopes.
- Match entries add `league_abbrev,main_league_abbrev,main_league_name,sub_league_abbrev,sub_league_name,stage_type,is_placeholder,is_bye,status` to the Catigoal fields. A populated individual run has `team2:null` and no awarded points; a generated bye retains its BYE team representation. Exact-selection response envelopes also identify the selected hierarchy.
- `GET /rest/v1/openapi.yaml` serves the embedded OpenAPI 3.0.3 specification from `src/web/docs/rcgamemaster_restapi_v1_openapi.yaml`, including response formats, filters, and examples. It is public and uses the REST CORS policy. The supplied root-level Catigoal YAML remains unchanged.

## Frontend routes

`/`, `/tournaments/:id/setup`, `/tournaments/:id/games` (optional `?stage=ID`), `/tournaments/:id/schedule`, `/tournaments/:id/standings`, `/tournaments/:id/review`, `/referee`, `/referee/:id`, `/public/:abbrev`, `/display/:abbrev`, `/display/:abbrev/fields/:fieldId`. The display also accepts `?field=ID`, with no selector or fullscreen button. Vue uses hash history, so browser links include `/#/`. Shared Axios clients use `/api/v1` and `/api/public`; private views render inside AppShell, while public pages and the TV presentation run without sign-in.

Stage games opens a Catigoal-style league list beside stage buttons. Choosing a stage opens its draw and sets `?stage=ID`; a direct link opens that stage. **Change league / stage**, or the sidebar's **Stage games** link, reopens the chooser. **Clear draw** offers a confirmation for all saved games, with a latest-round option for multi-round Swiss, knockout, and manual stages. Successful clearing invalidates local drafts/previews and reloads the stage before another draw. Empty games show **Awaiting teams**, remain schedulable and publishable, and are excluded from result review and referee control. A placeholder has `is_placeholder:true,team1_id:0,team2_id:null`; it is not a bye and never contributes a result or a team-conflict check.

The Match schedule **Main league** filter includes the chosen main league and its sub-leagues for both games and fields. The browser stores this choice per tournament in `localStorage` under `schedule.mainLeague.ID`. Missing, invalid, or removed-league values fall back to all main leagues. Filtering remains usable if storage is unavailable.

An individual run has `team1_id` set, `team2_id:null,is_bye:false,is_placeholder:false` after population. It retains its reserved match ID, duration, field, time, referee assignments, and publication. It is never automatically approved or published. Each team has one run per individual stage; create a separate stage for another run. Public pages and displays show a single team and **Individual run**, then **Completed** after approval, without an opponent or paired score.
